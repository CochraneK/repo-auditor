## P1 · 高优先收口

### 1. GitHub 仓库 Profile 还没有真正配置

GitHub API 当前返回：

- `description = null`
- `homepage = null`
- `topics = []`

但仓库已经有 `docs/repository-profile.md`。

这意味着“想怎么展示”已经写好了，“GitHub 搜索/主页实际上怎么看到”还没落地。

**建议：**把 description、Safe Demo homepage、topics 真正配置到 GitHub repository profile。

---

### 2. GitHub Actions 供应链还没有达到 Model Vault 同等级标准 · **FIXED**

当前 workflows 大量使用：

- `actions/checkout@v4`
- `actions/setup-python@v5`
- `github/codeql-action/...@v3`
- `actions/upload-artifact@v4`
- `aquasecurity/trivy-action@v0.36.0`
- `anchore/sbom-action@v0.17.2`

这些是 mutable tag。

而 Model Vault 已经使用：

> immutable upstream revision + SHA-256

安全工具自身的 CI supply chain 最好统一标准。

**建议：**第三方 Actions 全部 pin 到 reviewed commit SHA，并在旁边保留版本注释。

---

### 3. `security-boundary` badge 的实际测试范围比名字窄 · **FIXED**

`.github/workflows/security.yml` 当前显式运行：

- `tests/test_policy.py`
- `tests/test_pipeline.py`

但真正验证：

- private worker 有 raw + no network；
- model setup 有 network + no private mount；
- cloud worker 只有 safe mount；

的是 `tests/test_deployment_contract.py`。

它现在由 general test workflow 覆盖，而不是 security-boundary workflow。

**建议：**把 deployment contract、Model Vault boundary 等直接加入 security-boundary workflow，让 badge 的语义与真实 claim 对齐。

## P2 · 重要但不阻断

### 4. CI / dev 环境缺少锁定策略

作为 Python library，runtime dependency 使用范围约束没有问题。

但 CI / dev 环境目前没有看到：

- `uv.lock`
- `poetry.lock`
- constraints lock
- 等价方案

这会使未来“昨天绿、今天解析出不同 transitive dependency”更难复现。

**建议：**保留 library-friendly runtime ranges，同时给 CI/dev 建独立 lock/constraints 更新流程。

---

### 5. Tag build 有 artifact，但还没有 release attestation/signing

`release.yml` 当前负责：

- build
- upload artifact

这已经是好基础，但还没做到：

- provenance/attestation；
- signature；
- 明确 GitHub Release / PyPI 发布策略。

在 pre-1.0 阶段完全可以接受；正式发布前补。

---

### 6. Branch protection / rulesets 本次无法验证

这是**未验证**，不是“确认没有”。

当前 GitHub connector 没有 repository administration 权限，不能据此判断 protected main / required checks。

正式 release-hardening 前人工确认一次即可。

## 已经做得很好的地方

Long Gate 当前最强的部分不是“功能多”，而是**边界逐渐变成可执行约束**：

1. capability separation 比 prompt guardrail 更可信；
2. raw / pseudonymized row-level data 默认禁止出关；
3. synthetic 不等于 exact inference，真实统计可以本地算；
4. semantic transformation 没被包装成匿名化；
5. public demo 不部署 private worker；
6. Model Setup 与 Private Processing 拆成不同能力集；
7. model download 既 pin upstream revision，又验 SHA-256；
8. Trust Report / provenance / benchmark / non-claims 都比较克制；
9. Release Readiness 已做 clean-venv wheel install；
10. 项目文档面已经具备明星仓库基础。
